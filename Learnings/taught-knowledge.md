## 2. Architecture & system design (DSA problem-solving)
- Start from a simple correct/brute-force model, identify repeated work, then optimize only when constraints require it; do not pick an algorithm merely because it is the current topic. (source: `sources/scaler-dsa/T-Scaler Edge DSA Intermediate transcript part 1.md`, pair-sum brute force ~01:04–01:10 and nested-loop analysis ~01:21–01:43; `sources/scaler-dsa/T-Scaler Edge DSA Advance transcript part 1.md`, Painter’s Partition ~00:38–00:42)
- Define DP state from the brute-force subproblem and distinguish state parameters from accumulated objective value; establish base cases and fill in dependency order. (source: `sources/scaler-dsa/T-Scaler Edge DSA Advance transcript part 2.md`, 0–1/unbounded knapsack ~01:07–01:23, ~02:10–02:28; palindrome interval DP ~01:49–02:00; matrix-chain section ~01:30 onward)
- Binary search on answer requires a candidate range, feasibility predicate, and monotonic direction; choose bound updates for the correct minimum-feasible or maximum-feasible boundary. Complexity is `log(answer range) × check cost`, not automatically `log n`. (source: `sources/scaler-dsa/T-Scaler Edge DSA Advance transcript part 1.md`, Painter’s Partition ~01:10–01:32; Aggressive Cows ~02:04–02:30)
- For nearest-time propagation from several sources, initialize a BFS queue with all sources; process level-by-level, use the stated adjacency (e.g. four directions), and return the required no-solution value when targets remain unreachable. (source: `sources/scaler-dsa/T-Scaler Edge DSA Advance transcript part 1.md`, Rotten Oranges/multisource BFS ~00:12–01:08)
- Bipartite check is two-coloring with conflict detection; BFS or DFS are presented, and every component must be checked if disconnected graphs are possible. Treat the course’s odd-cycle discussion as a coloring algorithm explanation, not a replacement for the explicit conflict check. (source: `sources/scaler-dsa/T-Scaler Edge DSA Advance transcript part 1.md`, graph coloring ~01:08–02:06; `sources/scaler-dsa/T-Scaler Edge DSA Intermediate transcript part 2.md`, bipartite tree ~02:07–02:33)
- Select a data structure for the required operation: heaps support repeated min/max extraction, not general search; BST operations rely on whole-subtree ordering; two-pointer methods exploit sorted order only when guaranteed. (source: `sources/scaler-dsa/T-Scaler Edge DSA Advance transcript part 3.md`, heaps ~00:09–00:53 and ~01:41–02:49, BST ~00:11–01:31, two pointers ~00:08–00:41)
- Derive complexity from actual traversal, dimensions and constraints. Nested loops are not automatically quadratic if bounds/breaks limit total movement; constant-factor fewer comparisons do not change asymptotic class; required output may be excluded from auxiliary-space accounting. (source: `sources/scaler-dsa/T-Scaler Edge DSA Intermediate transcript part 1.md`, loop counting ~00:18–00:25, pair comparisons ~01:18–01:35, consecutive-ones break analysis ~01:21–02:04; `sources/scaler-dsa/T-Scaler Edge DSA Advance transcript part 2.md`, output-vs-auxiliary space ~01:40–02:02)
- Use dry runs to expose edge cases: duplicates, zeros, one/empty inputs, unreachable states, and no feasible answer. Use lower-bound reasoning when every input element must be inspected or changed. (source: `sources/scaler-dsa/T-Scaler Edge DSA Intermediate transcript part 1.md`, array/product cases ~00:18–00:57, reverse lower bound ~01:57–02:04; `sources/scaler-dsa/T-Scaler Edge DSA Advance transcript part 1.md`, unreachable oranges ~00:19–00:23)
- Treat wall-clock speed and asymptotic complexity separately; alternative representations are acceptable when correctness and stated time/space bounds remain the same. (source: `sources/scaler-dsa/T-Scaler Edge DSA Intermediate transcript part 1.md`, complexity conventions ~00:47–00:52; `sources/scaler-dsa/T-Scaler Edge DSA Advance transcript part 2.md`, fractional-knapsack alternatives ~00:32–00:41)

## 3. Coding conventions & patterns
- Default to language-agnostic algorithm reasoning; syntax, integer division, collection APIs, ordering, and pass/mutation semantics must be checked for the target language. (source: `sources/scaler-dsa/T-Scaler Edge DSA Intermediate transcript part 1.md`, arrays/syntax ~00:20–00:26; `sources/scaler-dsa/T-Scaler Edge DSA Intermediate transcript part 2.md`, map APIs ~00:35–00:55)
- Keep array index and value distinct in dry runs; for in-place tasks mutate the supplied data rather than silently returning/printing a replacement. Count auxiliary arrays as O(n), fixed helper variables as O(1). (source: `sources/scaler-dsa/T-Scaler Edge DSA Intermediate transcript part 1.md`, array basics ~00:12–00:15, reverse/rotate ~01:40–02:26)
- Choose map when values/frequencies are associated with keys and set when only membership/distinctness is needed; check membership before retrieving potentially absent keys. (source: `sources/scaler-dsa/T-Scaler Edge DSA Intermediate transcript part 2.md`, map/set and frequency examples ~00:42–01:59)
- Ensure keys uniquely identify records when the domain allows duplicate names; values may be scalars, lists, or nested structures. (source: `sources/scaler-dsa/T-Scaler Edge DSA Intermediate transcript part 2.md`, key/value examples ~00:17–00:41)
- Keep paired record fields together during sorting; use a comparator or auxiliary derived value for the comparison key. Heap indices in a zero-based array use left `2i+1`, right `2i+2`, parent `(i−1)/2` with target-language integer division. (source: `sources/scaler-dsa/T-Scaler Edge DSA Advance transcript part 2.md`, fractional knapsack/envelopes ~00:31–00:41, ~01:16–01:25; `sources/scaler-dsa/T-Scaler Edge DSA Advance transcript part 3.md`, heap representation ~00:55–01:04)
- For tree/list structural deletion or replacement, update links and track parent/child relationships rather than copying a potentially large node payload. (source: `sources/scaler-dsa/T-Scaler Edge DSA Advance transcript part 3.md`, BST deletion ~01:08–01:21)
- Do not assume hash-map traversal order; sort keys/results separately if deterministic order is required and allowed by the problem. (source: `sources/scaler-dsa/T-Scaler Edge DSA Intermediate transcript part 2.md`, map iteration order ~00:57–01:04)
